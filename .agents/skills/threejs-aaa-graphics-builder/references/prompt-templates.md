# Graphics Prompt Examples

Use only for requested reusable prompts. Adapt the named surfaces, target view
and evidence to the actual task; repository art and production rules remain
authoritative. These examples do not authorize providers, new systems or subagents.

## Authored graphics pass

Use $threejs-aaa-graphics-builder to improve [named asset/scene surfaces] toward
[current art brief or reference characteristics]. Observed misses: [evidence].
Trace each miss to its owner, improve form/spacing/material/light as relevant,
and inspect the integrated result at [gameplay distance and affected conditions].
Use existing production systems and proportionate checks. Report the visible
improvements, evidence and remaining gaps; human approval remains separate.

## Before/after critique

Use $threejs-aaa-graphics-builder to review [views or live scene] against
[accepted brief]. Identify the highest-impact defects in the named surfaces,
with visible evidence and an actionable next pass. Inspect motion if making
temporal claims. This request is analysis only; do not edit. Use qualitative
findings rather than numeric scores or image-complexity metrics.

## Material or lighting pass

Use $threejs-aaa-graphics-builder to resolve [observed material/light issue]
in [affected scene]. Preserve the shared palette and renderer ownership.
Inspect the relevant gameplay views and lighting/tier transitions; measure cost
when the implementation changes render work. Add post-processing only for a
clear purpose permitted by the art brief.

## Procedural asset or prop family

Use $threejs-aaa-graphics-builder’s model critique references for [asset IDs or
family] with [silhouette, scale, read distance, intended construction and budget].
Build in the project’s owning generator; in Neva use the catalog and registered
Blender family. Inspect form, material, collision/attachment and motion as relevant.
Do not add a runtime factory, fixed prop count or provider requirement.

## Technical art

Use $threejs-aaa-graphics-builder for [specific resource or architecture issue].
Reuse existing owners and diagnostics, record matching baseline/post evidence,
and preserve the intended image and supported tiers. Explain measured tradeoffs
and unresolved risks without adding an unrelated graphics framework.

## Independent visual review, when authorized

Review [affected views/motion and technical evidence] against [brief and scope].
Identify visible defects, missing evidence and the most useful corrections.
Keep technical measurements separate from aesthetic judgment and human approval.
This prompt is for an expressly requested reviewer; it is not a mandatory phase.
